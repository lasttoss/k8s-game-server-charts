Incident · k8s-game-server-charts

The response packets were the egress

A NetworkPolicy that allowed ingress on the game server's port and egress only to DNS produced a pod that was 1/1 Running, a kubelet probe that answered in five microseconds, and a client that hung until it timed out.

source: docs/incidents/networkpolicy-blocked-its-own-service.md · verified on kind (kindnet) · chart commit c2328f3 · the fix is in templates/networkpolicy.yaml

Rule worth keeping

A pod that serves traffic has to allow the traffic back out. “Egress only what it starts itself” describes a client; for a server, the response is egress of that pod.

Three experiments, one variable each: that is the whole investigation.
